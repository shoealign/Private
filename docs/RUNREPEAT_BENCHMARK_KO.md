# RunRepeat 비교 및 KICKLINEUP 개선 기록
조사/수정: 2026-10-10

## 비교한 원문
- 러닝화 목록: https://runrepeat.com/catalog/running-shoes
- EVO SL 리뷰/비교표: https://runrepeat.com/adidas-adizero-evo-sl
- Alphafly 3 리뷰: https://runrepeat.com/nike-alphafly-3
- 테스트 방법: https://runrepeat.com/testing-methodology
- 서비스 소개: https://runrepeat.com/about
- 배포 설정: https://vercel.com/docs/project-configuration

이 문서는 위 공개 페이지를 직접 열어 확인한 UI/정보구조와 이번 프로젝트의 코드를 비교한 것입니다.
RunRepeat 전체 서비스의 모든 기능을 조사하거나 성과를 측정한 감사는 아닙니다.

## 핵심 판단
RunRepeat에서 참고할 장점은 방대한 수치를 그대로 옮기는 것이 아니라,
무엇을 비교하는지와 그 근거를 분리해서 보여주는 정보구조입니다.
KICKLINEUP은 실험실을 갖춘 서비스가 아니므로 실측형 수치를 새로 만들지 않았습니다.
로그인/댓글/사용자 리뷰를 받지 않는 기존 운영 범위를 유지했습니다.

## 이번에 바꾼 내용

### 1. 비교 버튼과 카드 높이
기존 파일은 이름과 정보 길이에 따라 행동 버튼이 서로 다른 높이에 있었습니다.
카드 본문을 flex-column 구조로 정리하고 하단 행동 영역을 바닥에 맞췄습니다.
관심/비교 버튼은 같은 44px 높이와 같은 폭을 사용합니다.
여러 페이지에서 쌓인 서로 충돌하는 CSS 대신 공통 스타일을 사용합니다.

### 2. 실제 비교 페이지
기존 /compare/ 페이지는 메인으로 다시 이동해 비교창을 열도록 안내했습니다.
이제 /compare/에서 바로 표가 나옵니다.
제품을 최대 3개 선택하고 같은 행에서 유형, 거리, 발볼, 와이드, 사이즈 의견, 점수, 자료, 발매가를 비교합니다.
같은 값이 있는 행은 접을 수 있고, 서로 다른 값은 약한 배경으로 표시합니다.
2개 제품은 모바일에서도 나란히 보이고 3번째 제품은 가로로 넘깁니다.
현재 선택을 URL에 담아 같은 비교 조합을 공유할 수 있습니다.
비교 페이지에는 하단 비교 담기 바를 중복 표시하지 않습니다.

### 3. 상세정보 우선순위
RunRepeat 제품 페이지는 요약, 장단점, 추천/비추천 대상, 비교표, 시험자료를 구분합니다.
KICKLINEUP에는 요약 → 장점/주의 → 발볼/사이즈 → 리뷰 → 구매처 → 함께 비교할 모델 순서를 적용했습니다.
긴 페이지는 내부 목차로 이동합니다.
같은 시리즈의 모델은 독립 상세페이지로 연결하고 관련 모델을 바로 비교에 담을 수 있게 했습니다.

### 4. 리뷰와 공식 자료를 따로 집계
검색 링크/공식몰/판매처 링크까지 리뷰로 보이던 문제를 정리했습니다.
개별 전문 리뷰와 커뮤니티/블로그/영상 링크만 리뷰 건수로 계산하고 URL 중복을 제거합니다.
자료 유형별 필터와 원문 링크를 추가했습니다.
기존 자료와 실제 재열람한 자료를 구분했습니다.
이번에 새로운 리뷰를 수십 건 수집한 것은 아닙니다.

### 5. 점수 투명성
RunRepeat은 자체 테스트 방법과 제품별 리뷰 방법 버전을 공개합니다.
KICKLINEUP의 기존 점수는 그와 같은 실측 점수가 아니므로 ‘참고 점수 / 산식 검증 전’으로 표시합니다.
소수 둘째 자리 표기는 유지합니다.
출처 개수로 신뢰도 91/100 같은 값을 만들어 보이던 부분은 제거했습니다.
임의의 AggregateRating을 검색엔진 구조화 데이터로 내보내지 않습니다.

### 6. 발볼과 사이즈
기본 모델의 발볼 체감과 와이드 출시 여부를 분리했습니다.
자료 미확인을 ‘보통’으로 채우지 않습니다.
서로 다른 원문에 사이즈 의견이 다르면 ‘의견 차이’로 보여줍니다.
거리만으로 자동 반업, 내구성 점수만으로 교체 한도, 훈련거리를 대회 출전 횟수로 단정하는 표시는 숨겼습니다.
기존 원본 필드와 리뷰 사용거리 자체를 삭제한 것은 아닙니다.

### 7. MY LINEUP
5단계 입력과 모름 선택을 유지합니다.
완료하면 MATCH 순으로 정렬합니다. 브라우저에 저장해 재접속 시 복원합니다.
MATCH는 조건 일치 점수이며 실제 착화 성공 확률이 아닙니다.
발볼/용도/거리/경험에 명시적 가중치를 쓰고 연결 근거가 없는 케이던스/체중/색상 입력은 억지로 가산하지 않습니다.
모든 입력의 제품 추천 효과가 검증됐다는 인상을 주지 않도록 안내했습니다.

### 8. 관리 구조
assets/shoes.json을 단일 제품 데이터 원본으로 사용합니다.
Node 기본 기능만으로 shoes.js, 메인/상세/비교/안내 페이지, 사이트맵을 생성합니다.
Vercel 빌드 결과 public 폴더만 배포해서 운영 메모나 빌드 도구가 사이트 메뉴에 섞이지 않도록 했습니다.
기본 응답 보안 헤더를 추가했지만 전체 서비스 보안을 보증하는 것은 아닙니다.

## 유지한 것
51개 모델, 8개 브랜드, 한국어 별명 검색, LINE 순위 표기, 목적별 탭,
작은 한눈에 보기, 비교/관심 목록, KREAM 외부 확인, 공식 제품/검색 링크,
제휴 메일, 광고 자리 비활성화.

## 이번에 완료하지 않은 것
- 51개 제품의 원본 사진을 모두 로컬 파일로 확보
- 51개 국내 발매가/출시일/SKU/재고 전수 검증
- 모든 기존 리뷰 원문의 유효성 및 요약 내용 전수 재검증
- 재현 가능한 근거 데이터에 기반한 LINEUP SCORE의 재산정
- iPhone Safari 및 실제 Vercel 배포 주소에서의 전체 테스트

따라서 ‘실데이터 검증이 모두 완료된 정식 서비스’라고 표시하지 않았습니다.
